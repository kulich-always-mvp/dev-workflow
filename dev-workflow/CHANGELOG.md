# История изменений dev-workflow

## 3.2 — 2026-10-29

Закрыты пути обхода механических проверок, найденные разбором v3.1 и проверкой сторожа на краевых командах. Самотест: 616 проверок пяти скриптов (было 406 трёх).

### Скрипты
- Новый `guard-edit.sh` — хук на Read, Write, Edit, MultiEdit, NotebookEdit, Grep. Раньше сторож видел только Bash, и правка файла инструментом обходила его целиком. Правила: `hooks` (git-хуки, `.git/config`, настройки агента, файлы регламента, списки заморозки), `secrets` (`.env` и другие файлы с секретами), `tests` (правка строк существующих и замороженных тестов; дописывать новые тесты можно, если вставка без пропусков, подавлений и досрочного `return`).
- `guard-bash.sh`, новые правила: `secrets` (`env`/`printenv` без аргументов, `export -p`, `echo $…TOKEN`, `cat`/`head`/`grep` по `.env` и ключам) и `delete-tracked` (`rm -r`, `find -delete`, `git rm -r` каталогов с файлами под git, удаление закоммиченных тестов). `discard` ловит откат целого каталога или маски (`git restore -- src/`, `git checkout HEAD -- tests/`). Проверяется код внутри `python -c`, `node -e`, `perl -e`, `ruby -e`, `php -r`. `hooks` защищает скрипты и `SKILL.md` регламента, списки заморозки и `.git/config`.
- Исправлено: сторож блокировал чтение `git config core.hooksPath`, хотя Discovery велит выполнить именно его. Теперь блокируются только установка и сброс.
- Проба `true dev-workflow-guard-probe`: сторож всегда блокирует её с текстом «активен». Если она выполнилась, сторож не подключён — раньше он отключался молча (например, при установке skill плагином). В поиск скриптов добавлен `$CLAUDE_PLUGIN_ROOT/skills/dev-workflow`.
- `GUARD_ASK`: правило из списка не блокирует, а отправляет пользователю запрос подтверждения (`permissionDecision: "ask"`) — только в режимах прав `default`, `acceptEdits`, `plan`; в остальных блокирует. `hooks` не спрашивает никогда. По умолчанию спрашивает только `tests` в `guard-edit.sh`.
- `freeze.sh record` больше не перезаписывает список молча: повторная запись — только с `--reason`, прежние строки и причина сохраняются, `verify` показывает число перезаморозок. Оба режима печатают отпечаток списка.
- Новый `session-reminder.sh` для хука `SessionStart`: после сжатия контекста напоминает об активной задаче из `.ai/ACTIVE`.

### Регламент
- Отложить работу, когда коммит невозможен (хуки проекта гоняют тесты, коммиты запрещены): патч в папку задачи вместо `wip`-коммита — раньше легального способа не было.
- Класс S включает небольшую новую функцию с очевидным поведением; различаются добавление в API и изменение существующего API. Для S — карточка прямо в `SKILL.md` (ветка, коммит, отчёт), без чтения справочников: экономия ~20 КБ контекста на мелкой задаче.
- Для M первый профиль проекта показывается в одном сообщении с гейтом ТЗ.
- Явно сказано, что включённый регламент — поручение коммитить в ветке задачи, даже если среда по умолчанию коммитит только по просьбе; политика подтверждается на гейте профиля.
- Общение и отчёты — на языке пользователя; файлы и коммиты — по профилю.
- Инварианты: слитую `integration/…` можно удалять; откат целого каталога запрещён; секреты не открываются целиком, структура `.env` — через маскировку.
- Независимое ревью без субагентов: задание передаётся пользователю, ревью отмечается как не проведённое.
- `.ai/ACTIVE` — указатель на активную задачу; удаляется при архивации.
- В отчётах — строка «Сторож: активен | не активен» и отпечаток списка заморозки.

### Сценарии
- README перечисляет все сценарии (`secrets-stay-hidden` был пропущен).
- Новые сценарии: вопрос без правок (класс 0), посторонний тест, красный в Baseline, refactor с контрольной поломкой, отмена тестов пользователем, небольшая новая функция как класс S.
- В каждый сценарий добавлена проверка, что skill вообще был использован.

## 3.1 — 2026-10-28

Исправления по итогам разбора v3.0 и проверки скриптов на тестовых репозиториях. До исправлений самотест давал 186 провалов из 366 проверок, после — 0 из 406.

### Безопасность
- Отложенная работа — коммитом в ветку `parked/<slug>/step-N`, а не `git stash push -u`: stash уносил незакоммиченные правки пользователя, общий для всех worktree, а номера `stash@{n}` сдвигаются. Stash — только для правок пользователя по его выбору, с записью SHA.
- Свою неудачную правку можно откатить пофайлово (`git restore -- <файл>`); массовый откат по-прежнему запрещён.
- Служебная папка `.ai/` всегда в основной рабочей копии (`git worktree list --porcelain`): раньше в автономном режиме архив задачи удалялся вместе с worktree, а воркеры не видели спецификацию. Контракт воркера содержит полный текст требований.
- `.ai/` скрывается через `.git/info/exclude` — файлы репозитория (`.gitignore`) больше не меняются.
- Защищённые ветки (`main`, `master` и список из профиля), исключение для первого коммита в пустом репозитории; работа в ветке пользователя по умолчанию строится от неё, а не от `main`.
- Перед первым Baseline агент проверяет, не ходят ли тесты в боевые сервисы и БД.
- В инвариант 4 добавлены удаление чужих веток, деплой и публикация, `git config --global`.

### Скрипты
- `guard-bash.sh` переписан: разбирает только текст команды (`jq` или встроенный разбор), понимает `bash -c "…"`, `eval`, heredoc, обёртки и разделители без пробелов. Добавлены правила: `commit -n`, `core.hooksPath`, `HUSKY=0`, `+ветка` и `:ветка` в push, `stash drop/clear`, `branch -D/-f`, защищённые ветки, `-u` в jest/vitest, глобальные установки, `wget`/`iwr | iex`, разрушающие запросы к БД, деплой и публикация, удаление корня/дома/`.git`. Убраны ложные срабатывания на поле description и текст коммитов. Настройки пользователя: `~/.claude/dev-workflow.conf` или переменные `DEV_WORKFLOW_*` (отключить правило, список защищённых веток, выключить целиком).
- Сторож включается сам: блок `hooks` во frontmatter `SKILL.md` регистрирует его, когда skill вызван в Claude Code. Codex этот блок игнорирует (проверено по исходникам парсера). Для загрузки в claude.ai блок нужно удалить.
- `check-commit.sh`: исправлены пути с кириллицей и пробелами (`core.quotePath=false`, срез TAB), разбор diff устойчив к строкам `-- …` и настройкам `diff.noprefix`/`mnemonicPrefix`/внешнему diff. Новые правила: коммит `test`, меняющий существующие тесты, не может менять код; коммит `wip` разрешён в ветке `parked/…`, но не в истории задачи. Расширены списки подавлений, тестовых путей и конфигов проверок. `--help` → код 0, `--range` без `..` → код 2.
- Новый `freeze.sh`: заморозка тестов контрольными суммами, когда хуки проекта не дают сделать красный коммит; сверка с рабочей копией или с коммитом.
- Новый `selftest.sh`: 406 проверок трёх скриптов, в том числе без `jq`; изолирован от настроек пользователя.

### Регламент
- Заморожены все тесты, существовавшие на момент Baseline. Механическая правка теста (импорты, имена) — мягкий гейт, правка по существу — жёсткий.
- Refactor: вместо красного статуса — контрольная поломка.
- Класс S: мини-Baseline до правки, источник команд без `PROJECT.md`, тест в существующем файле — коммитом `test(...)` после `fix(...)`.
- Новый тип задач `docs`. Честный пропуск или подавление — только через жёсткий гейт.
- Профиль проекта: защищённые ветки, политика для класса S, «коммиты агентом», хуки проекта, способ заморозки, способ слияния.
- Короткая форма отчёта о шаге (три строки с доказательством); полная — при отклонениях и блокерах.
- `check-commit.sh --range` обязателен перед ревью; архивация — до удаления worktree.
- Windows: оговорка о `timeout` в PowerShell, `.gitattributes` с `eol=lf`, хуки через Git Bash; в git-хуках — копия скрипта в репозитории вместо пути к `~/.claude`.
- Описание skill сформулировано настойчивее, чтобы агент не забывал его вызывать; версия хранится только в `metadata.version`.

### Новое
- `references/example-m.md` — образец заполненной задачи M от запроса до приёмки.
- `evals/` — 6 сценариев проверки поведения агента в формате `claude plugin eval` (соблазн поправить тест, автономный режим с чужими правками, опечатка класса S, инъекция в комментарии, хуки с тестами, ветка пользователя).

## 3.0 — 2026-10-28

Переработка «Протокола разработки и ведения проекта (AI Workflow) v2.1» (файл `регламент_v3.md`) в skill. В скобках — идентификаторы предложений из анализа.

### Архитектура
- Монолитный промпт превращён в skill по открытому стандарту Agent Skills: `SKILL.md` с полями `name`/`description`, работает в Claude Code и Codex (A1).
- Прогрессивная загрузка: ядро `SKILL.md`, справочники `references/` открываются перед своей фазой, шаблоны `templates/` (A2).
- Три слоя: инварианты (неотменяемые) / процесс / справочник. Инварианты стоят в начале ядра, потому что после сжатия контекста сохраняется начало skill (A3).
- Классификация по двум осям: размер S/M/L по признакам риска × тип задачи со своей стратегией проверки; класс 0 для запросов без изменения кода; повышение класса по ходу работы (A4, I7, I8).
- Таблица гейтов (мягкие/жёсткие) и три режима: интерактивный, полуавтономный, автономный (A5). Для M — один гейт на ТЗ и план.
- Постоянный профиль проекта `.ai/PROJECT.md`: команды, таймауты, Baseline, политика git и языка (A6, I29).
- Необязательные механические проверки: `scripts/check-commit.sh` (git-хук для любого агента и CI) и `scripts/guard-bash.sh` (хук Claude Code) (A7).
- Разделение ролей: в L красные тесты пишет оркестратор в фазе 0, воркерам правка тестов запрещена; независимый ревьюер обязателен для L (A8, I30).
- Новая фаза «Ревью и закрытие»: самопроверка диффа, документация, архивация якорей, уборка worktree (A9).
- «Порядок запуска» стал единственным маршрутом со ссылками, без самостоятельных правил (A10).
- У ключевых правил указана причина (A11).
- Порядок приоритетов правил и явная отмена шагов пользователем с записью в журнал (A12).
- Единая версия в `metadata.version` и этот файл (A13, I6).

### Инструкции
- Каркас интерфейса с заглушками до тестов — снято противоречие с «красным по правильной причине» (I1).
- Точка заморозки тестов: до неё агент правит свои новые тесты, после — только через гейт и отдельный коммит `test` (I2).
- Откат только через `git stash push -u`, никогда не отбрасывать правки (I3).
- «Минимальный, но общий» код; самопроверка на других валидных данных (I4).
- Гейт плана перенесён в таблицу гейтов (I5).
- Проверка грязного рабочего дерева; в автономном режиме — отдельный worktree (I9).
- Частичный Baseline, flaky-тесты, проект без тестов (I10–I12).
- Лимиты вопросов: S — 0, M — до 5, L — до 10 (I13).
- Нормализация имени папки задачи `feature/x` → `feature-x` (I14).
- Права на изменение SPEC / PLAN / PROGRESS разведены (I15).
- Ориентир размера шага: ~300 строк, ~7 файлов (I16).
- Место хранения матрицы трассировки (I17).
- Расширенный список запретов антиподгонки: подавления линтера и типов, конфиги тестов, снапшоты, «починка» Baseline-падений (I18).
- Ритм прогонов: тесты шага после каждой правки, полный набор — в конце шага (I19).
- Ошибки окружения эскалируются сразу; лимит ~15 действий без прогресса (I20).
- Тесты проверяют поведение через публичный интерфейс (I21).
- Багфикс: тест-воспроизведение и корневая причина в отчёте (I22).
- Расширен список действий, требующих согласия (I23); правила для секретов (I24); таймауты по умолчанию (I25); требования к запросу на зависимость (I26).
- Push и PR — только по просьбе или по профилю проекта (I27); Conventional Commits с описанием на русском (I28).
- Изоляция ресурсов worktree, критерии «когда не распараллеливать», обработка провала воркера (I31–I33).
- Поля «Не проверено» и «Отклонения» во всех отчётах; формат доказательства; язык артефактов (I34–I36).
