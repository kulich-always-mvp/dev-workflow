# Форматы отчётов

Общие правила:
- Доказательство — команда и сводка её вывода (`412 passed, 0 failed`), плюс релевантные строки при ошибках. Не весь лог.
- Поля «Не проверено» и «Отклонения» заполняются всегда; если пусто — «нет».
- Запрещены формулировки «всё работает», «должно работать», «скорее всего исправлено» без вывода проверки.

## Отчёт о шаге

По умолчанию — короткая форма в чат, три строки:

```
Шаг 2/5 «Разбор CSV» — ЗАВЕРШЁН · REQ-1, REQ-2
Проверка: pytest tests/test_csv.py → 12 passed; полный набор: 431 passed, 3 failed (те же, что в Baseline)
Коммиты: a1b2c3d test(csv), d4e5f6a feat(csv) · Не проверено: нет · Отклонения: нет
```

Полная форма — если шаг заблокирован или есть отклонения, допущения или непроверенное; она же сохраняется в журнале:

```
Шаг N: <название> — ЗАВЕРШЁН | ЗАБЛОКИРОВАН
Требования: REQ-…
Изменённые файлы: …
Красный статус: <команда> → <сводка, причина падения> (для refactor — контрольная поломка)
Заморозка: коммит <sha> test(...) | freeze.sh verify → «Заморозка цела», отпечаток <sha списка>, перезаморозок: 0
Проверка: <команда> → <X passed, 0 failed>; сверка с Baseline: новых падений нет
Линтер / типы / сборка: <итог или «не применялось»>
Коммиты: <sha> test(...), <sha> feat(...)
Не проверено: … (почему)
Отклонения от плана/спецификации: …
Допущения: …
Следующий шаг: …
```

## Отчёт для класса S

```
Класс S · <тип> — <что сделано одной фразой>
Файлы: …
Проверка: <команда> → <сводка> (до правки: <красный вывод, если был тест>)
Коммит: <sha> <сообщение> · Ветка: <ветка> (как забрать: …)
Не проверено: … · Сторож: активен | не активен
```

## Эскалация

```
БЛОКЕР на шаге N: <кратко>
Что падает: <команда> → <релевантные строки вывода>
Проверенные гипотезы:
  1. <гипотеза> — <что сделал> — <почему не подтвердилась>
  2. …
Вид блокера: ошибка кода | окружение | противоречие спецификации | архитектурный тупик | нужна команда, заблокированная сторожем
Состояние: ветка <…>, последний зелёный коммит <sha>, отложено — parked/<slug>/step-N (<sha>) | parked-step-N.patch | нет
Что нужно от пользователя: решение / доступ / информация / пересмотр плана / выполнить команду: <команда>
Предложение: …
```

## Блок автономного режима

Держи вверху журнала задачи и финального отчёта:

```
Режим: автономный
Принятые допущения: [ДОПУЩЕНИЕ A-1] …, [ДОПУЩЕНИЕ A-2] …
Заблокировано: шаг 4 — нужна новая зависимость <…>; шаг 6 — нужен доступ к <…>
Ждёт решения пользователя: …
```

## Финальный отчёт

```
Задача: <название> · Класс <…> · Тип <…> · Режим <…>
Итог: выполнено полностью | частично (см. «Заблокировано»)

Требования (матрица трассировки):
  REQ-1 <кратко> → test_… ✔
  REQ-2 <кратко> → test_…, test_… ✔
  REQ-3 <кратко> → непокрыто: <почему>

Проверки (финальный прогон) и сверка с Baseline:
  тесты: <команда> → было 412/3 failed, стало 431/3 failed (те же 3, см. Baseline)
  линтер: было 12, стало 12 · типы: 0 → 0 · сборка: ок
  check-commit.sh --range <база>..HEAD → нарушений нет | не запускался (почему)
  сторож: активен (проба заблокирована) | не активен

Независимое ревью: проведено | не проводилось (почему); находки и что с ними сделано
Известные ограничения и технический долг: …
Предложения вне рамок задачи: …
Допущения без явного ответа пользователя: …
Отменённые пользователем шаги процесса: …
Не проверено: …
Коммиты: <sha> …
Как проверить самостоятельно:
  git checkout <ветка> && <команды>
Как забрать результат: <git merge --ff-only <ветка> из ветки пользователя | PR | ждёт решения о слиянии>
```
